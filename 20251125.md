# YouTube Data API — `part` Parameter Rules (Clean Summary)

## 1. Different endpoints support different `part` values
Each YouTube Data API endpoint has its own allowed `part` values.  
You cannot mix parts arbitrarily.

---

## 2. `search.list` — Only allows **`snippet`**
`search.list` is a lightweight endpoint for discovering videos.

### ✅ Valid:
```

part=snippet

```

### ❌ Invalid:
```

part=id
part=id,snippet
part=snippet,statistics

```

Even though the response includes an `id` object,  
`id` is **not** a valid `part` for search.

---

## 3. `videos.list` — Supports multiple parts
`videos.list` provides full details about a video.

### ✅ Valid:
```

part=id
part=snippet
part=statistics
part=snippet,statistics

```

---

## 4. Why the difference?
- **search.list**  
  - Optimized for fast, lightweight queries  
  - Only returns minimal metadata  
  - Strict part restriction for efficiency

- **videos.list**  
  - Returns full, rich video information  
  - Supports flexible, multiple part fields

---

## 5. Simple Rule
```

✔ Use part=snippet for search
✔ Use flexible parts (e.g., snippet,statistics) for videos

```
